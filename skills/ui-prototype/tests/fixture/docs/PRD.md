## 1. 概述

一家 60 人的食品加工厂，采购部 6 人（5 名采购员、1 名采购主管）目前用 Excel 和微信管理供应商与采购单：单子散在各人电脑里，主管审批靠截图，月底对账要花两天。本期做一个内网的采购协同系统：采购员登记采购单，主管在线审批，供应商资料集中维护。成功标准：上线一个月后，所有采购单都在系统里提交和审批，主管的平均审批时间从 1 天降到 4 小时以内。

## 2. 用户与角色

| 角色 | 能做 | 不能做 |
|---|---|---|
| 采购员 | 查看供应商；新建、提交、撤回自己的采购单；查看所有采购单 | 新建、编辑、停用供应商；审批采购单；打开审批工作台 |
| 采购主管 | 采购员能做的全部；新建、编辑、停用供应商；审批或驳回采购单；使用审批工作台 | 修改别人的草稿采购单 |

## 3. 需求

### 3.1 角色与导航  REQ-001

系统只有两个角色：采购员、采购主管。侧栏导航按角色显示：采购员看到「概览、采购单、供应商」，主管多一个「审批」。没有权限的页面直接打开地址时，显示「没有访问权限」页，不显示数据。

- AC1 Given 当前用户是采购员陈静 When 打开任意页面 Then 侧栏只有「概览」「采购单」「供应商」三个入口
- AC2 Given 当前用户是采购主管李想 When 打开任意页面 Then 侧栏有「概览」「采购单」「供应商」「审批」四个入口
- AC3 Given 当前用户是采购员陈静 When 直接打开 /approvals Then 显示「没有访问权限」页，不显示任何待审批采购单

### 3.2 概览  REQ-002

概览页给当前用户看本月的采购情况：本月采购额（已通过的采购单金额合计）、待审批（状态为「待审批」的采购单数）、本周到货（预计到货日期在本周内、且已通过的采购单数）、逾期未到货（预计到货日期早于今天、状态仍为「已通过」的采购单数）。下方列出最近 5 张采购单。

- AC1 Given 本月已通过的采购单金额合计 ¥1,286,400.00 When 打开概览 Then「本月采购额」显示 ¥1,286,400.00
- AC2 Given 有 6 张待审批采购单 When 打开概览 Then「待审批」显示 6，点它跳到采购单列表并筛选为「待审批」
- AC3 Given 有 2 张逾期未到货的采购单 When 打开概览 Then「逾期未到货」显示 2，并用红色标出

### 3.3 供应商列表  REQ-003

列出全部供应商，支持按名称或编号搜索、按状态（合作中 / 待审核 / 已停用）和类别（原材料 / 包装材料 / 物流服务 / 设备维修）筛选，按更新时间倒序，每页 20 条。

- AC1 Given 有 46 家供应商 When 打开供应商列表 Then 第一页显示 20 家，底部显示「共 46 条」
- AC2 Given 列表里有「杭州恒信包装有限公司」 When 搜索「恒信」 Then 只显示名称或编号含「恒信」的供应商
- AC3 Given 筛选状态为「已停用」且没有符合条件的供应商 When 列表为空 Then 显示「没有符合条件的供应商」和「清除筛选」按钮

### 3.4 供应商详情  REQ-004

详情页显示供应商的基本信息（编号、名称、类别、状态、评级、统一社会信用代码）、联系人信息，以及和它有关的最近 10 张采购单。

- AC1 Given 供应商 SUP-0012 有 14 张采购单 When 打开它的详情 Then「最近采购单」列出最近 10 张，按下单日期倒序
- AC2 Given 供应商编号 SUP-9999 不存在 When 打开 /suppliers/SUP-9999 Then 显示「页面不存在」

### 3.5 新建与编辑供应商  REQ-005

只有采购主管能新建和编辑供应商。必填：名称（2–40 字，不能和已有供应商重名）、类别、联系人、联系电话（11 位手机号）、统一社会信用代码（18 位）。新建的供应商状态为「待审核」。

- AC1 Given 当前用户是李想 When 填写完整并点「创建」 Then 提示「已创建供应商」，回到列表，新供应商排在第一位，状态「待审核」
- AC2 Given 已有名为「杭州恒信包装有限公司」的供应商 When 用同样的名称创建 Then 名称下方提示「已有同名供应商」，不创建
- AC3 Given 当前用户是陈静 When 打开 /suppliers/new Then 显示「没有访问权限」页
- AC4 Given 正在编辑且有未保存的修改 When 点侧栏的其他入口 Then 弹出「放弃未保存的修改？」确认

### 3.6 停用供应商  REQ-006

主管可以在供应商详情页停用一个「合作中」的供应商，需要填写停用原因（必填，不超过 100 字）。已停用的供应商不能出现在新建采购单的供应商选择里。

- AC1 Given 供应商 SUP-0003 状态为「合作中」 When 李想在详情页点「停用」、填写原因并确认 Then 状态变为「已停用」，提示「已停用」
- AC2 Given 供应商 SUP-0007 已停用 When 新建采购单选择供应商 Then 下拉列表里没有 SUP-0007

### 3.7 采购单列表  REQ-007

列出全部采购单，Tab 分为「全部」「我创建的」「待审批」；支持按单号或供应商搜索、按状态和下单日期范围筛选；每页 20 条，按下单日期倒序。

- AC1 Given 有 132 张采购单，其中陈静创建 31 张 When 陈静打开「我创建的」 Then 显示 31 张
- AC2 Given 选择下单日期 2026-10-01 至 2026-10-15 When 筛选 Then 只显示这段时间内下单的采购单
- AC3 Given 系统里还没有任何采购单 When 打开采购单列表 Then 显示「还没有采购单」和「新建采购单」按钮

### 3.8 新建采购单  REQ-008

采购员和主管都能新建采购单：选择供应商（只能选「合作中」的）、预计到货日期（不早于今天）、明细行（物料名称、规格、数量、单价，至少一行，最多 50 行），金额自动合计。可以「存为草稿」或「提交审批」。

- AC1 Given 明细两行：面粉 25kg × 40 袋 × ¥128.00、白砂糖 50kg × 10 袋 × ¥265.00 When 填写 Then 合计显示 ¥7,770.00
- AC2 Given 没有填写任何明细行 When 点「提交审批」 Then 提示「至少添加一行明细」，不提交
- AC3 Given 填写完整 When 点「提交审批」 Then 生成单号（PO-年月日-三位序号，如 PO-20261020-007），状态「待审批」，跳到这张单的详情

### 3.9 采购单详情与撤回  REQ-009

详情页显示单号、状态、供应商、创建人、下单日期、预计到货日期、明细行与合计、审批记录。创建人可以撤回自己「待审批」的采购单，撤回后变回「草稿」。

- AC1 Given 陈静创建的 PO-20261018-003 状态为「待审批」 When 陈静点「撤回」并确认 Then 状态变为「草稿」，审批记录新增「陈静 撤回」
- AC2 Given PO-20261015-001 是王晓创建的 When 陈静查看它 Then 不显示「撤回」按钮

### 3.10 审批采购单  REQ-010

主管在采购单详情或审批工作台中通过或驳回「待审批」的采购单；驳回必须填写原因（不超过 200 字）。金额超过 ¥50,000.00 的采购单通过时要再确认一次。

- AC1 Given PO-20261019-002 待审批、金额 ¥12,600.00 When 李想点「通过」 Then 状态变为「已通过」，提示「已通过」
- AC2 Given PO-20261019-005 待审批、金额 ¥86,000.00 When 李想点「通过」 Then 先弹出「金额超过 ¥50,000.00，确认通过？」，确认后才通过
- AC3 Given 李想点「驳回」 When 没填原因就确认 Then 提示「请填写驳回原因」

### 3.11 审批工作台  REQ-011

主管专用：列出所有「待审批」的采购单，按提交时间正序（先提交的在前），可以勾选多张一起通过；金额超过 ¥50,000.00 的不能批量通过，需要单独审批。

- AC1 Given 有 6 张待审批采购单 When 李想打开审批工作台 Then 列出 6 张，最早提交的在第一行
- AC2 Given 勾选了 3 张金额都不超过 ¥50,000.00 的采购单 When 点「批量通过」 Then 3 张都变为「已通过」，提示「已通过 3 张采购单」
- AC3 Given 勾选的采购单里有一张金额 ¥86,000.00 When 点「批量通过」 Then 提示「金额超过 ¥50,000.00 的采购单需要单独审批」，不做任何更改

- 假数据：与采购单列表同一份数据，指标照 REQ-002 的 AC 取值（本月采购额 ¥1,286,400.00、待审批 6、逾期 2）；近 6 个月采购额每月一根柱子。

### 4.3 采购单详情（order-detail）

- 类型：详情
- 入口：采购单列表、概览、审批工作台
- 布局：页头（单号、状态徽标、操作按钮）→ 左侧「基本信息」与「明细」（物料、规格、数量、单价、小计，底部合计），右侧「审批记录」时间线
- 字段：基本信息（供应商、创建人、下单日期、预计到货日期、备注）；明细行；审批记录（时间、人、动作、原因）
- 操作：

| 操作 | 位置 | 结果 | 权限 |

| 通过 | 页头 | 超过 ¥50,000.00 时二次确认；变为已通过 | 主管，且状态为待审批 |
| 驳回 | 页头 | 弹窗填写原因；变为已驳回 | 主管，且状态为待审批 |

- 状态：单号不存在时显示「页面不存在」；其余照通用约定。
- 假数据：每张 1–8 行明细；PO-20261018-003（陈静，待审批）、PO-20261015-001（王晓创建）、PO-20261019-002（¥12,600.00，待审批）、PO-20261019-005（¥86,000.00，待审批）四张要能打开。

### 4.6 供应商详情（supplier-detail）

- 类型：详情
- 入口：供应商列表、采购单详情里的供应商名称
- 布局：页头（名称、状态徽标；主管可见「编辑」「停用」）→ 左侧「基本信息」，右侧「联系人」→ 下方「最近采购单」表格（10 条，不分页）
- 字段：基本信息（编号、类别、评级、统一社会信用代码、合作开始日期、备注）；联系人（姓名、手机、邮箱）；最近采购单（单号、金额、状态、下单日期）
- 操作：编辑（主管，打开编辑页）；停用（主管，弹窗填写原因，见 REQ-006）
- 状态：编号不存在时显示「页面不存在」；没有采购单时「最近采购单」显示「还没有采购单」。
- 假数据：SUP-0012 有 14 张采购单；SUP-0005 一张都没有。

### 4.7 新建 / 编辑供应商（supplier-form）

- 类型：新建编辑
- 入口：供应商列表「新建供应商」、供应商详情「编辑」
- 布局：整页表单，一个「基本信息」分组（名称、类别、评级、统一社会信用代码），一个「联系人」分组（姓名、手机、邮箱）；底部「取消」「创建 / 保存」
- 字段：见 REQ-005；评级默认 B；邮箱选填，要符合邮箱格式。
- 操作：创建 / 保存；取消（有改动时确认）
- 状态：采购员打开显示「没有访问权限」；编辑时编号不存在显示「页面不存在」。
- 假数据：同供应商列表。

### 4.8 审批工作台（approvals）

- 类型：列表
- 入口：侧栏「审批」（只有主管）
- 布局：页头（标题、待审批数量）→ 表格（可多选；选中后出现「批量通过」）；点行打开采购单详情
- 字段：单号、供应商、金额（超过 ¥50,000.00 的加「需单独审批」标记）、创建人、提交时间
- 操作：批量通过（见 REQ-011）；点行打开详情审批
- 状态：没有待审批时显示「没有待审批的采购单」；采购员打开显示「没有访问权限」。
- 假数据：采购单里的 6 张待审批单，其中 PO-20261019-005 金额 ¥86,000.00。

## 6. 通用约定

- 金额显示为 ¥ 加千分位、两位小数（¥12,600.00）；日期 2026-10-18，日期时间 2026-10-18 14:20。
- 列表每页 20 条；空状态分两种：一条数据都没有时显示「还没有…」和新建按钮（没有新建权限时不显示按钮）；筛选后没有结果时显示「没有符合条件的…」和「清除筛选」。
- 文本字段保存前去掉首尾空白。
- 权限不足：没有权限的按钮不显示；直接打开没有权限的页面显示「没有访问权限」。
- 读取失败显示「加载失败」和「重试」；提交失败用提示条显示原因，已填内容保留。
