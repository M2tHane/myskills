# ui-prototype

根据 PRD 快速做出可点击的前端原型，让人逐页看。在 `/grill-spec` 之后、pi-forge `/forge-build` 之前运行。流程细节见 [SKILL.md](SKILL.md)。

## 要做到什么

原型只为让人看，不追求功能真的生效：

1. 每一页都画出来。
2. 会弹窗的按钮点了能弹出，能看到弹窗内容。
3. 保存、通过、删除这类按钮不用真的生效，点了只弹一句提示。
4. 列表显示假数据：只要有、格式像样，不用真实，各页之间也不用对得上。有分页条，翻页可以不生效。
5. 页面之间能正常跳转。
6. 页面顶栏正中能一键切换四种状态：加载中、空数据、出错、无权限。
7. 不分角色：按权限最大的角色显示全部页面和按钮。
8. 验收标准是给真实开发看的。原型只从里面取交互（有哪些按钮、弹出什么、提示什么），不管里面的数字。
9. 一个 agent 按顺序做，不并行。

## 怎么实现

| 步骤 | 做什么 |
|---|---|
| 0. 检查输入 | 读 PRD 的页面表和每页的规格；quick 模式（还没有 PRD）跳过 |
| 1. 选套件 | 套件在 `kits/`，目前只有 [Strata](kits/strata/README.md)，直接用 |
| 2. 搭工程 | 照套件的 KIT.md 在 `docs/prototype/` 复制骨架、组件、脚本，装依赖，类型检查通过 |
| 3. 写页面 | 列表、详情、表单先用脚本生成空壳：路由、导航、四种状态、跳转、删除弹窗、提示、30 条假数据都已接好；再照 PRD 填列、字段、按钮和弹窗。概览这类页面照套件样板写。类型检查和规范检查都要通过 |
| 4. 填技术栈 | 把前端技术栈写进 `docs/ARCHITECTURE.md` 的「3. 前端」 |
| 5. 验收 | agent 先截图自查（正常状态每页都看，四种状态抽查），改完再交给用户：只给预览地址、自己定下的界面细节、PRD 里功能上的缺口。用户逐页看，选「通过」或提修改意见 |
| 6. 交付 | 打包成双击就能打开的 `app.html`，每页写一个跳转页，删掉依赖和截图，跑 `scripts/check-export.mjs`，交给 pi-forge |

还没有 PRD 时可以先 `/ui-prototype quick <想看的页面>` 做几页；有了 PRD 再运行 `/ui-prototype`，在原地补齐。

## 目录

| 路径 | 内容 |
|---|---|
| `SKILL.md` | agent 执行的流程 |
| `kits/` | UI 套件，每套一个文件夹，入口是 `KIT.md` |
| `scripts/check-export.mjs` | 交付前检查：原型和 PRD 能不能直接作为 pi-forge 的输入 |
| `tests/` | 示例 PRD（8 页、两个角色）和计时方法 |
